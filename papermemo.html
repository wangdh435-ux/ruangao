🧠 三篇论文范文 · 记忆要点

骨架先行：通用模子 + 分论点清单 + 好记数字 + 结尾套路，背完再读范文

🧩 通用骨架：三篇范文同一个模子

  1. 背景两段式：第 1 段 = 单位 + 痛点（三甲医院 / 信息孤岛 / 重建设轻运维）；第 2 段 = 项目要素（中标时间、金额、周期、建设或服务内容）+ 我的角色（系统规划与管理师）+ 团队构成与人数
  2. 过渡段固定句式：「良好的 ×× 是项目成功的关键，我首先 … 随后／接下来 … 最后 …，具体过程如下」——三个分论点在此预告
  3. 正文三大块：一、二、三、各成一段群，每块公式 = 理论一句话 → 步骤/活动清单 → 结合项目的数字化实例 → 小成效
  4. 结尾两段式：验收时间 + 关键指标 + 满意度 → 三点经验 → 不足与改进 → 学习展望（ITSS 等）

💡 三篇共用同一套「三甲医院」背景：背熟一套背景，考场上换论点即成新文。背景 6 要素：单位规模、痛点、中标时间/金额/周期、内容、我的角色、团队构成。

① 论云资源规划读范文全文 →

项目：三甲中心医院云一体化，1260 万 / 14 个月，8 大功能域，26 人 6 组，私有云 + 等保 2.0 三级。

分论点一：四种云服务模式的联系和区别

  • 联系：层次递进、相互支撑、抽象层次渐高（IaaS 底座 → PaaS 中间件/容器 → SaaS 成品软件 → FaaS 事件函数）
  • 区别：服务层次、使用对象、管理边界（IaaS 管系统管理员 / PaaS、FaaS 面向开发 / SaaS 面向普通用户）
  • 选型原则：核心敏感选私有云 IaaS，互联网弹性选 PaaS/FaaS，通用办公选 SaaS

分论点二：计算资源规划 七步

需求分析 → 容量规划 → 云服务选择 → 虚拟化策略 → 安全性考虑 → 成本效益分析 → 持续监控维护

分论点三：存储资源规划 九步

收集需求 → 分析评估 → 技术选择 → 架构设计 → 安全规划 → 容量规划 → 性能优化 → 管理监控 → 定期评估调整

好记数字

32 台虚拟机、200TB 对象存储、PACS 年增 80TB、资源成本降 30%、利用率 20%→55%、调阅 ≤2 秒、预留 20% 余量、五年 600TB、病历保存 30 年。

结尾

经验 3 条：摸清底数定混合云路线 / 计算存储分步规划留余量 / 安全与成本同步落地。不足：挂号峰值估低 → 扩容阈值 80% 调到 65% + 月度容量复盘。

② 论 IT 服务业务关系管理读范文全文 →

项目：中心医院信息综合平台运维，460 万 / 1 年，8 人团队，按 SLA 保障 7×24 不间断。

分论点一：客户关系管理 7 活动 + 2 风险

活动：定期沟通、日常沟通、高层拜访、投诉管理、表扬管理、满意度调查、增值服务

风险：① 未识别关键客户真正需求（高层要的是评审指标，不只是系统稳定）② 干系人多、需求多样（按科室差异化服务报告 + 补充协议）

分论点二：供应商管理 5 活动 + 3 风险

活动：选择、审核及管理、供应商间协调、争议处理、支持合同管理；关键句：对供应商的合同标准始终高于对客户的 SLA（客户 99.9%/2 小时 ↔ 供应商 99.95%/1 小时），预留缓冲。

风险：多供应商配合推诿 / 供应商组织变动 / 供应商不配合 → 固定协作机制 + 应急演练、备份供应商、评估更换 + 争取其高层支持。

分论点三：服务营销 四阶段

启动准备 → 调研交流 → 能力展示 → 服务达成（准备=营销准备+营销计划；调研=需求调研+方案论证；展示=演示环境+实地考察+持续沟通；达成=SLA 协商签约+持续经营挖掘新需求）

好记数字

可用率 99.95%、工单响应 12 分钟、满意度 92%→97%、表扬信 11 封、供应商评分 72→89、SLA 达标 99.2%、新签 280 万 + 次年 80 万。

结尾

经验 3 条：客户是业务连续的关键 / 全过程严管供应商形成合力 / 统筹协调第三方。不足：需求识别不充分、人员离职 → 需求变更 + 增补人员。

③ 论应用系统规划读范文全文 →

项目：信息综合平台规划，1160.57 万 / 1 年，8 人团队，通过互联互通标准化成熟度四级测评。

分论点一：生命周期模型选择

瀑布 / V / 迭代 / 敏捷 → 选迭代模型中的增量建设（结合 V 模型思路），三期 6+5+4 个月；增量集成 2 个关键：① SOA + 统一 ESB 保证架构开放 ② 每期上线前全量回归测试。

分论点二：可行性研究 八步

复查目标规模 → 研究现有系统 → 导出高层逻辑模型 → 重新定义问题 → 导出并评价供选方案（经济/技术/社会/管理） → 推荐方案 + 成本效益分析 → 草拟开发计划 → 撰写可研报告（专家论证会），前四步可循环修正。

分论点三：规划方法组合拳 APA + TOGAF + SOA

  • APA 应用系统组合法：盘点 23 个系统，四维度评估 → 保留升级 4 / 替换 8 / 淘汰 3 / 整合 8
  • TOGAF ADM：预备 → 需求 → 架构愿景 → 业务/信息系统/技术架构（先基线后目标，差距分析 37 项缺口）→ 机会与解决方案（15 个项目排序）→ 迁移规划（三期路线图）
  • SOA 落地：42 个粗粒度、松耦合标准化服务 + 统一 ESB + 服务注册中心与治理

好记数字

需求 460 余项、日门诊 9000 人次、挂号 15→6 分钟、处方差错降 42%、数据共享率 20%→95%、三方案报价 860/680/750 万。

结尾

经验 3 条：模型选择好（提前 1 个月验收）/ 充分可研降风险 / 正确方法是指路明灯。不足：招标文件与合同需求描述不一致 → 沟通解决。

✍️ 应试提示

  • 三篇范文正文直接从背景开始，未含摘要；正式考试需先写 300 字左右摘要（背景一句 + 三个论点一句 + 成效一句），再展开正文。
  • 每个分论点段落套用公式：理论一句 → 步骤清单 → 项目实例（带数字） → 小成效，数字是阅卷加分点。
  • 背记顺序建议：先背通用骨架和三篇的分论点清单（七步 / 九步 / 7+2 / 5+3 / 四阶段 / 八步 / APA-TOGAF-SOA），再用好记数字填血肉。
